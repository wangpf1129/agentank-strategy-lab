# Shield Main 策略架构

本文档描述 `active/shield-main.js` 的护盾坦克策略边界。它把 field manual 的宏观打法和本仓库的 real-review bounded evolution 流程合在一起：手册负责定义打法方向，仓库方法负责把方向变成可复盘、可测试、可回滚的迭代。

参考来源：

- AgentTank Field Manual：https://mifunetron.github.io/agentank-field-manual/zh.html
- 本仓库训练方法：`docs/agentank-evolution-method.md`

验证边界：

- 手册只负责生成假设，例如主动权、确认命中、草丛信息差、技能 matchup 和排名经济。
- 护盾主逻辑仍然以本文档的 L0-L8 优先级为准，不能因为手册里的宏观建议直接覆盖生存硬约束。
- 任何手册导出的策略都必须进入本仓库流程：真实 replay 标签、一个 bounded axis、回归测试、`check/test/sim/dry-run`，再决定是否发布。
- 判断有效不看单场观感，而看一组真实样本里的胜率、分数净变化、回撤、子弹死亡、护盾转换、星线保留和草丛收益。

护盾坦克不是传送坦克，也不是超载坦克。它的核心身份是：

```text
星线低方差反击手：用护盾承接确定风险，用星星和枪线逼对手犯错。
```

## 帧的含义

一帧就是游戏做一次决策和状态推进的最小时间单位。坦克的 `turn`、`go`、`fire`、`shield` 都会消耗当前帧的行动机会，子弹、技能冷却、护盾剩余时间、敌方位移也都按帧推进。

因此策略不是“看到危险就躲”这么简单，而是比较帧经济：

- 我方这一帧能否直接离开枪线。
- 敌方这一帧能否转向或开火。
- 护盾剩余帧数是否足够完成吃星、反打或离线。
- 子弹到达我方格子的 ETA 是否小于我方逃离成本。
- 草丛、星星、障碍物是否会改变下一帧双方信息差。

任何模块如果抢走更高优先级模块的一帧，就可能让坦克从优势变成白给。

## 总原则

优先级从高到低：

1. 生存硬约束
2. 主动权和枪线帧经济
3. 护盾转换
4. 星星节奏
5. 战略草丛
6. 确认压制
7. 对手技能剧本
8. 领先/落后尾盘策略
9. 普通路径、炸弹、解卡和巡逻

任何新策略必须属于其中一层。不能在主逻辑末尾追加一个不受优先级管理的 `tryXxx()`。

## L0 生存硬约束

处理内容：

- 当前子弹和未来几帧子弹 ETA。
- 敌方已瞄准或一帧可瞄准的直线枪线。
- 破土后一枪线。
- 超载偏移弹道。
- 隐身/草丛隐藏射手。
- 自己炸弹爆炸范围。

规则：

- 硬危险不能被星星、草丛、追击或普通开火覆盖。
- 护盾可以临时承接硬危险，但必须同时满足“护盾剩余帧能转化价值或离线”。
- 护盾即将结束时，回到危险优先，不继续吃星或追击。

复盘信号：

- `hard-current-bullet-eta`
- `hard-breakable-cover-shot`
- `hard-close-aimed-duel`
- `fix-bullet-death`
- `fix-post-shield-reset`

## L1 主动权和枪线帧经济

处理内容：

- 同一行/列上谁先能开火。
- 我方是否已经瞄准，是否需要转向。
- 当前朝向是否能一帧离开枪线。
- 敌方是否刚开火、刚开技能、刚进入冷却。

规则：

- 已经面对出口并能一帧离线时，优先离线，不要多转一帧。
- 已经瞄准且敌方没有护盾/硬掩体时，可以确认开火。
- 对方子弹刚发出、技能进入冷却、或为了星星暴露路线时，要抢主动权，而不是退到没有价值的位置。
- 输掉主动权的典型形态是我方无压制、对方连续开火或控住星线。

复盘信号：

- `preserve-initiative-pressure`
- `brave-initiative-pressure`
- `fix-lost-initiative`
- `fix-no-pressure-loss`

## L2 护盾转换

处理内容：

- 开盾后吃星。
- 开盾后反打。
- 开盾后穿过短枪线进入优势位。
- 开盾后离开致命线，避免盾结束站死。

规则：

- 护盾不是“逃跑按钮”，也不是“无脑冲按钮”。
- 开盾后优先寻找可确认价值：星星、击杀、迫使敌方离线、或安全退出枪线。
- 对方在射击范围内且我方护盾仍覆盖交换时，不要白白退走。
- 如果盾只挡了一帧但没有吃星、开火、换位或离线，这就是空耗。

复盘信号：

- `preserve-shield-conversion`
- `brave-shield-conversion`
- `fix-shield-no-conversion`
- `risk-wasted-shield`

## L3 星星节奏

处理内容：

- 安全近星。
- 同路竞速。
- 已经领先时的低方差控星。
- 落后时的拦截、压线和强制交换。

规则：

- 安全相邻星优先级很高，除非存在 L0 硬危险。
- 如果抢星已经输了，不继续直线追星，改为控星线、截出口或逼对手转向。
- 领先时不急着进危险星线，对方急才是我们的收益来源。
- 落后时不能无策略绕路，要用护盾、草丛或枪线制造对方必须响应的帧。

复盘信号：

- `preserve-star-tempo-win`
- `brave-safe-star`
- `fix-star-tempo-loss`
- `fix-no-value-created`

## L4 战略草丛

草丛不是默认目的地，只分三类：

- 战略草丛：能控星线、控敌方出口、制造隐藏枪线或逼对手绕路。
- 中转草丛：能低成本进入下一颗星线或压力位。
- 死草丛：不控星、不控人、不出枪线，只会挂机。

规则：

- 战略草丛可以高于普通吃星路径，但不能高于 L0、L1、L2 和安全近星。
- 进入草丛前必须证明它控制当前星线、下一颗可能星线、敌方路线或我方反打线。
- 草丛停留要有退出条件：几帧内没有星线价值或压制价值，就离开。
- 对抗传送/隐身草丛坦克时，不走进疑似隐藏枪线；用盾、星差和路线封锁逼它出来。

复盘信号：

- `preserve-grass-leverage`
- `brave-strategic-grass`
- `fix-dead-grass`

## L5 确认压制

处理内容：

- 直线无遮挡且已瞄准的开火。
- 敌方吃星路线上的封锁枪线。
- 敌方技能/子弹冷却后的惩罚窗口。
- 对草丛蹲点坦克的出口压制。

规则：

- 不为了“有进攻”浪费空枪。
- 不射击敌方护盾，除非这是为了阻断路线或时间窗口。
- 开火要满足至少一个价值：命中、逼退、封星线、破土开路或延迟对手。
- 开火后要确认自己没有站在对方下一帧可回复的枪线上。

复盘信号：

- `preserve-clear-kill-pressure`
- `brave-clear-fire`
- `fix-facing-without-shot`

## L6 对手技能剧本

传送/Riftwalker：

- 默认假设它会用草丛和传送制造信息差。
- 关注上次落点和可达草丛，不盲走草线。
- 我方领先时用星差和安全星线逼它出来；落后时用护盾抢关键星或压它出口。

护盾镜像：

- 不对敌方护盾浪费弹。
- 看谁能在盾后先转化星星或退出枪线。
- 近身对射只在我方盾覆盖且能转化时成立。

超载：

- 不只看正面直线，还看两侧偏移弹道。
- 障碍物旁边尤其危险，第二颗子弹可能绕开直觉安全位。
- 护盾可承接短窗口，但盾后必须离线或反打。

隐身：

- 记录最后可见帧和移动方向。
- 草丛/同线缺失信息按隐藏枪线处理。
- 不能因为敌人不可见就默认星线安全。

加速/控制类：

- 加速会改变竞速帧数，安全近星仍要重新算 ETA。
- 眩晕、冰冻、中毒、反向控制优先归入 L0/L1；先确保当前帧动作真实有效。

## L7 领先/落后尾盘

领先：

- 降低方差，控安全星线和战略草丛。
- 让对方必须冒险进入枪线或草丛出口。
- 不为了多一炮离开优势位。

落后：

- 提高价值密度，但不放弃 L0。
- 优先制造对手必须响应的帧：护盾抢星、封星线、草丛出口压制。
- 不能无压制绕路，不能长期不发弹。

## L8 普通路径、炸弹、解卡和巡逻

这些是兜底层，不应该抢走前面模块：

- 普通路径只在没有硬危险、没有更高价值帧时执行。
- 炸弹用于近身陷阱、星区封锁和破路线，不随机消耗。
- 解卡只打断无价值循环，不能覆盖安全吃星和确认反打。
- 巡逻只在没有星、没有敌方信息、没有战略草丛时执行。

## 代码结构守则

`active/shield-main.js` 只能有一个 live 决策入口：`buildStrategyPipeline()` -> `runStrategyPipeline(...)`。

维护规则：

- 每个行动模块都必须有明确层级、唯一 id 和单一职责。
- pipeline 层级必须从 L0 到 L8 单调下行，不能把低层策略插到高层前面。
- 草稿策略可以留函数骨架，但不能进入 live pipeline；要启用时必须作为一个 bounded axis 单独验证。
- 新策略不能在文件末尾直接追加 `tryXxx()` 调用，必须进入 pipeline 并补静态顺序测试。
- 共享状态建模函数优先复用，例如护盾剩余帧、枪线 ETA、草丛价值和星线 ETA，避免不同模块各算各的。
- 任何结构调整都要先保证 `node --test lab/scripts/tests/shield-main-strategy.test.mjs` 通过，再进入全量 `check/test/sim/dry-run`。

## 迭代方法

继续沿用本仓库流程：

```text
真实样本 -> 行为评分 -> 标签聚类 -> 一个 bounded axis -> 测试锁定 -> check/test -> dry-run -> 明确确认后真实挑战
```

每轮只修一个行为轴。单场失败只要不是可复现硬约束，就先进入复盘标签，不直接改主逻辑。

本轮新增的复盘轴：

- `initiative-economy`：看谁在关键帧让对方先响应。
- `shield-conversion`：看护盾是否转化成星星、开火、击杀或离线。
- `grass-leverage`：看草丛是不是战略位，而不是死草丛挂机。

## 非目标

- 不把护盾坦克改成传送或超载打法。
- 不全局提高草丛优先级。
- 不用单场 match id 写分支。
- 不为了修防守删掉安全吃星、确认开火和护盾反打这些勇敢基准。

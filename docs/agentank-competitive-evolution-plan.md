# AgentTank 竞技强化演进计划

这份文档是在 `agentank-evolution-lab` 方法基础上，扩展出来的一套适合我们自己坦克的长期强化体系。目标不是堆规则，而是让坦克逐步形成“意识、策略、阵地、组织、规划”。

## 总目标

让 shield-main 成为一个有层次的竞技坦克：

- 有意识：能理解子弹、星星、敌方技能窗口、地形、分差、时间。
- 有策略：能区分开局、中盘、残局、领先、落后、平局。
- 有阵地：知道星线、枪线、盾反点、逃生点、破墙点、卡点。
- 有对局方案：面对传送、护盾、加速、隐身、毒、眩晕、冰冻、过载时有不同打法。
- 有强化闭环：真实案例会沉淀成保留行为、修复目标、硬约束、回归测试。

核心原则不变：不要因为一场失败就改坏整体。任何修复都必须保护已经证明有效的胜利行为。

## 方法基准

继续以 `agentank-evolution-lab` 为基准：

1. 以真实对局为准，不凭空脑补。
2. 胜利和失败都要复盘。
3. 致命风险是硬约束，不是普通扣分项。
4. 保留勇敢基准，不能越训越怂。
5. 每次只做一个清晰假设，保留回滚版本。
6. 模拟只是安全检查，真实天梯才是最终评估。

我们的扩展方向是：把行为拆成战术层、对局 playbook、案例库和发布门禁。

## 战略分层

### 第一层：生存硬约束

这些判断必须优先于吃星、开炮、追人：

- 当前和未来几帧内会命中的子弹。
- 近距离已瞄准互射。
- 过载直线和偏移枪线。
- 可破坏地形被打穿后的未来枪线。
- 隐身/草丛/最后可见方向带来的隐藏枪线。
- 自己炸弹的爆炸范围。
- 护盾即将结束或刚结束后的危险复查。

输出动作只能是：开盾、躲避、反打、原地卡线。不能在硬约束下继续追星。

### 第二层：价值节奏

这层决定坦克这一帧想赢什么：

- 安全吃星。
- 抢关键星线。
- 面对传送/加速时提前卡点。
- 用护盾强行突破被守的星。
- 清晰枪线开火。
- 落后或平局后期主动制造压力。

输出动作是：吃星、占线、开火、盾冲、压枪线。

### 第三层：阵地和地形

这是坦克的“阵地意识”：

- 传送/加速快到星时，不追屁股，先占星所在行列或邻近点。
- 直接吃星会输时，站在星附近可控点。
- 护盾挡住子弹后，尽量把格挡转换成反击枪线。
- 可破坏地形只隔一格时，要当成未来枪线，而不是安全墙。
- 破坏地形只服务于开星路或开枪线，不乱打墙。
- 炸弹只用于近身陷阱或星区封锁，不随机丢。

输出动作是：占点、转向、移动、打墙、丢雷、换线。

### 第四层：技能对局 playbook

每一种敌方技能都要有自己的打法、案例标签和回归测试。

#### 传送

当前状态：2300+ 分段最主要瓶颈。

目标：

- 不追传送坦克的尾巴。
- 先蹲星线或星附近关键点。
- 如果传送先拿星，要尽快制造枪线压力。
- 长局不能反复输成 1-5、2-6 这种星星大崩盘。

案例标签：

- `teleport-first-star-lost`
- `teleport-long-star-loss`
- `teleport-quick-kill-win`
- `teleport-post-shield-bullet-death`
- `teleport-camp-success`

#### 护盾镜像

当前状态：波动较大，但最近 40 场不是最高优先级。

目标：

- 观察敌方护盾是否激活、是否刚用完。
- 不向敌方护盾里浪费炮。
- 敌方护盾结束后立刻压枪线。
- 等反击窗口时不能白白丢星星节奏。

案例标签：

- `shield-mirror-star-loss`
- `shield-mirror-kill-win`
- `shield-mirror-wasted-shot`
- `shield-mirror-expiry-pressure`

#### 加速

当前状态：多数情况能打，但护盾后子弹死亡仍可能发生。

目标：

- 默认加速能重开枪线，不把它当静态对射。
- 用星星节奏和护盾时机压制，不全局后退。
- 只修 post-shield 安全，不破坏当前胜利节奏。

案例标签：

- `boost-star-win`
- `boost-gunline-reset`
- `boost-post-shield-death`

#### 隐身

目标：

- 记住最后可见位置和移动方向。
- 根据草丛/行列推测可能出现的隐藏枪线。
- 避免“没压制、没吃星、被隐身先手”的失败。

#### 毒、眩晕、冰冻

目标：

- 把控制和 debuff 视为移动风险修正。
- 保留当前对毒的星星节奏优势。
- 避免眩晕/冰冻后无压制死亡。

#### 过载

目标：

- 过载直线和偏移枪线都是硬约束。
- 不只看正面直线，也要看旁边一格的 offset lane。
- 护盾不是万能，如果护盾结束后还在枪线里，仍然要躲。

## 案例库

以后每场有价值的对局，都应该沉淀成一条紧凑案例，而不是把 raw replay 长期塞进仓库。

最小字段：

- `matchId`
- `codeVersion`
- `result`
- `enemyName`
- `enemySkill`
- `mapId`
- `scoreLine`
- `frameCount`
- `outcomeCategory`
- `preserveSignals`
- `fixSignals`
- `hardBreaches`
- `braveSignals`
- `caseTags`
- `decision`

案例标签描述模式，不描述具体 match id。

好标签：

- `teleport-long-star-loss`
- `post-shield-current-bullet`
- `safe-star-tempo-win`
- `clear-pressure-kill-win`
- `shield-mirror-star-tempo`
- `breakable-cover-lane`
- `early-no-pressure-death`

坏标签：

- `fix-mat_BreyDta3r9RHXfDhN`
- `enemy-weird`
- `move-better`

## 评估指标

不同阶段看不同指标。

### 天梯指标

- 净分变化。
- 峰值分。
- 收盘分。
- 胜率。
- 从峰值回撤多少。
- 按敌方技能拆分胜负。

### 行为指标

- 星星差。
- 开炮次数和开炮价值。
- 护盾使用次数和转换价值。
- 无压制失败次数。
- 护盾后死亡次数。
- 长局星星失败次数。
- runtime 或平局风险。

### 发布门禁

候选版本发布前必须满足：

- 保护行为测试通过。
- `npm run check` 通过。
- `npm run test:lab` 通过。
- 服务器模拟没有明显退化。
- 只有一个清晰假设。
- 有明确回滚路径。

发布后：

- 只跑有边界的真实样本。
- 出现明显回撤要停。
- 先分析胜负，再决定继续改还是回滚。

## 升级循环

固定循环：

```text
真实观察 -> 打案例标签 -> 保护胜利行为 -> 锁定一个瓶颈 -> 小补丁 -> 测试 -> 模拟 -> 必要时发布 -> 小样本真实验证 -> 保留/回滚/继续迭代
```

不要把多个无关修复塞进一个版本。如果当前瓶颈是传送池，就不要同时重写护盾镜像、炸弹、路径和开火。

## 版本策略

- 稳定线上版本：真实天梯证据最好的版本。
- 候选版本：本地有边界改动的版本。
- 回滚基线：上一个稳定线上版本。
- 实验版本：没有发布压力的新战术模块。

当前状态：

- 线上 v9 已发布。
- v9 目标是强化传送星线拦截、早期安全压枪线、护盾后复查。
- 下一步应该跑 20 场真实样本。
- 核心问题是：v9 是否改善传送密集池，同时不削弱清晰开火、护盾时机、安全吃星。

## 后续工具建设

下一步 repo 可以补这些工具，让案例库变成真正的训练资产：

1. `state/cases.jsonl`：长期保存紧凑案例。
2. `npm run case:add -- <match>`：把一场对局追加成案例。
3. `npm run case:report -- --skill teleport --version 9`：按技能/版本出报告。
4. 技能看板：传送、护盾镜像、加速、隐身。
5. 从重复硬约束失败里生成回归测试。

这样 token 消耗会更稳：raw replay 留在 `/tmp`，仓库只保存紧凑案例、决策和测试。
